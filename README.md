## 📂 โครงสร้างโปรเจกต์ (Project Structure)
โปรเจกต์นี้ใช้สถาปัตยกรรม **App Router** โดยใช้ **Route Groups** (โฟลเดอร์ที่มีวงเล็บ) เพื่อแยกโค้ดฝั่ง User และ Admin แต่ละฝั่งมี layout และเมนูของตัวเอง โดยโฟลเดอร์ `user` และ `admin` ภายในกลุ่มกำหนด URL เป็น `/user/...` และ `/admin/...`

| ฝั่ง | URL | หน้าที่ |
| --- | --- | --- |
| User | `/user` | ประวัติการแจ้งซ่อม |
| User | `/user/report` | แจ้งปัญหาใหม่ |
| User | `/user/ticket/[id]` | ติดตามใบแจ้งซ่อม |
| Admin | `/admin/dashboard` | ภาพรวมระบบ |
| Admin | `/admin/tickets` | ค้นหาและกรองเรื่องแจ้งทั้งหมด |
| Admin | `/admin/tickets/[id]` | รับเรื่อง ใส่หมายเหตุ ปิดงาน หรือยกเลิก |
| Admin | `/admin/reports` | รายงานรายเดือน ประเภทปัญหา และอาคาร |
| Admin | `/admin/settings` | ตั้งค่าระบบ |

เข้า `/` จะพาไป `/user` และเข้า `/admin` จะพาไป `/admin/dashboard` ส่วน URL เดิม `/report`, `/ticket/[id]`, `/dashboard`, `/kanban`, `/admin/kanban` และ `/settings` จะส่งต่อไปหน้าใหม่ผ่าน `next.config.mjs` ซึ่งเป็นไฟล์ตั้งค่าที่ Next.js ใช้อยู่

ปัจจุบันแยกเฉพาะหน้า เมนู และ URL โดยยังใช้ข้อมูลจำลองและยังไม่มีระบบล็อกอินหรือตรวจสิทธิ์ การเข้า URL ของ Admin จึงยังเปิดได้โดยตรง

### การทดลองฝั่ง Admin

เมนูหลักมี **ภาพรวม**, **จัดการเรื่องแจ้ง**, และ **รายงานสรุป** โดยหน้าเดิม `/admin/settings` ยังเปิดได้โดยตรง

- ภาพรวมแสดงจำนวนเรื่องแต่ละสถานะและรายการล่าสุด กดการ์ดสถานะเพื่อเปิดรายการที่กรองแล้ว
- จัดการเรื่องแจ้งค้นหาด้วยรหัส หัวข้อ รายละเอียด สถานที่ หรือผู้แจ้ง และกรองตามสถานะ อาคาร และประเภทปัญหา
- หน้ารายละเอียดแสดงข้อมูลผู้แจ้ง รูปแนบ และประวัติพร้อมเวลา รับเรื่องเพื่อเริ่มดำเนินการ เพิ่มหมายเหตุที่ผู้แจ้งเห็น และปิดงานเมื่อมีผลการแก้ไขหรือรูปแนบ
- การยกเลิกต้องระบุเหตุผล เรื่องที่เสร็จสิ้นหรือยกเลิกแล้วจะไม่สามารถแก้ไขได้
- รูปผลการแก้ไขรองรับ JPG, PNG และ WebP สูงสุด 3 รูป ขนาดรวมไม่เกิน 2 MB บันทึกพร้อมผลการแก้ไขเมื่อยืนยันปิดงาน
- รายงานนับตามเดือนที่แจ้งในเขตเวลาไทย รวมเรื่องยกเลิก และแสดงสถานะปัจจุบันของเรื่อง

ข้อมูลตัวอย่างและการเปลี่ยนแปลงเก็บใน `localStorage` ของเบราว์เซอร์ แท็บ User และ Admin บน origin เดียวกันจะเห็นสถานะ หมายเหตุ และผลการแก้ไขร่วมกัน User ตัวอย่างเห็นเฉพาะเรื่องของ `demo-user` การล้างข้อมูลเว็บไซต์จะคืนค่าข้อมูลตัวอย่าง ไม่ได้บันทึกลง Supabase และไม่แชร์ข้ามเบราว์เซอร์หรือเครื่อง ฟอร์มแจ้งปัญหาใหม่ยังเป็นหน้าตัวอย่างเดิม

โครงสร้างข้อมูลและกติกาสถานะอยู่ใน `src/lib/tickets.ts` ส่วนการจัดเก็บข้อมูลตัวอย่างอยู่ใน `src/lib/ticket-store.ts` เมื่อต่อฐานข้อมูลจริงต้องเพิ่มการตรวจสิทธิ์และการบันทึกประวัติฝั่งเซิร์ฟเวอร์

## 🤖 AI Context & Developer Rules (คำสั่งสำหรับ AI)

**[ATTENTION AI]:** หากคุณ (AI) ได้รับไฟล์ `README.md` นี้ไปวิเคราะห์เพื่อช่วยเขียนโค้ด กรุณาปฏิบัติตามกฎของโปรเจกต์อย่างเคร่งครัดดังนี้:

1. **Architecture:** โปรเจกต์นี้ใช้ `Next.js App Router` ห้ามเขียนโค้ดด้วยรูปแบบ Pages Router แบบเก่าเด็ดขาด
2. **Language & Types:** เขียนโค้ดด้วย `TypeScript` (`.tsx`, `.ts`) เสมอ และต้องกำหนด Interface/Type ให้ชัดเจน
3. **Styling:** ตกแต่ง UI ด้วย `Tailwind CSS` เท่านั้น ห้ามใช้ Inline CSS หรือสร้างไฟล์ `.css` เพิ่มเติมหากไม่จำเป็น
4. **Component State:** หาก Component ไหนต้องมีการโต้ตอบกับผู้ใช้ (เช่น มีฟอร์มกรอกข้อมูล, กดปุ่ม `onClick`, ใช้ `useState`) ต้องบังคับใส่ `"use client";` ไว้ที่บรรทัดบนสุดของไฟล์เสมอ
5. **Localization:** ข้อความที่แสดงผลบนหน้าเว็บไซต์ (UI Text) ต้องเป็น **ภาษาไทย** ทั้งหมด
6. **No Turbopack in Dev:** เนื่องจากระบบมีปัญหากับการประมวลผลภาษาไทยในโหมด Turbopack ให้หลีกเลี่ยงการแนะนำคำสั่งที่มี `--turbo`
