## 📂 โครงสร้างโปรเจกต์ (Project Structure)
โปรเจกต์นี้ใช้สถาปัตยกรรม **App Router** โดยใช้ **Route Groups** (โฟลเดอร์ที่มีวงเล็บ) เพื่อแยกโค้ดฝั่ง User และ Admin แต่ละฝั่งมี layout และเมนูของตัวเอง โดยโฟลเดอร์ `user` และ `admin` ภายในกลุ่มกำหนด URL เป็น `/user/...` และ `/admin/...`

| ฝั่ง | URL | หน้าที่ |
| --- | --- | --- |
| User | `/user` | ประวัติการแจ้งซ่อม |
| User | `/user/report` | แจ้งปัญหาใหม่ |
| User | `/user/ticket/[id]` | ติดตามใบแจ้งซ่อม |
| Admin | `/admin/dashboard` | ภาพรวมระบบ |
| Admin | `/admin/tickets` | ค้นหาและกรองเรื่องแจ้งทั้งหมด |
| Admin | `/admin/tickets/[id]` | ดูรายละเอียด รับเรื่อง หมายเหตุ ปิดงานพร้อมผล/รูป และยกเลิกพร้อมเหตุผล |
| Admin | `/admin/reports` | รายงานรายเดือน ประเภทปัญหา และอาคาร |
| Admin | `/admin/settings` | ตั้งค่าระบบ |

เข้า `/` จะพาไป `/user` และเข้า `/admin` จะพาไป `/admin/dashboard` ส่วน URL เดิม `/report`, `/ticket/[id]`, `/dashboard`, `/kanban`, `/admin/kanban` และ `/settings` จะส่งต่อไปหน้าใหม่ผ่าน `next.config.mjs` ซึ่งเป็นไฟล์ตั้งค่าที่ Next.js ใช้อยู่

ใช้ Supabase Auth ผ่าน Google OAuth ที่ `/login` เฉพาะบัญชี Google มหาวิทยาลัย `@lamduan.mfu.ac.th` พร้อม session ผ่าน cookies และ Proxy ของ Next.js ผู้ที่ยังไม่ล็อกอินหรือไม่มี Google identity ของมหาลัยจะถูกพาไปหน้าเข้าสู่ระบบ บทบาทอ่านจาก `profiles.role` ในฐานข้อมูลฝั่งเซิร์ฟเวอร์ บัญชี User เปิดหน้า Admin ไม่ได้ ผู้ดูแลเข้าได้ทั้งสองพื้นที่และมีปุ่มสลับพื้นที่/ออกจากระบบ ฝั่ง User ส่งเรื่องและรูป อ่านประวัติและรายละเอียดจาก Supabase จริงเฉพาะบัญชีที่ล็อกอิน หลังติดตั้ง SQL 03 ตาม [คู่มือส่งเรื่อง](docs/03_design/report-submission.md) หน้า Admin อ่านรายการ รายละเอียด Dashboard และรายงานจาก Supabase จริง โดยตรวจ role ฝั่งเซิร์ฟเวอร์และ RLS ทุกครั้ง การรับเรื่อง หมายเหตุ ปิดงาน และยกเลิกบันทึกจริงหลังติดตั้ง SQL 04 ตาม [คู่มือ Admin](docs/03_design/admin-ticket-actions.md) ส่วนหน้าตั้งค่ายังเป็นตัวอย่าง

ตั้งค่า `.env.local` จาก `.env.example` ใช้ Project URL, Publishable key และ `NEXT_PUBLIC_SITE_URL` แล้วเริ่มเซิร์ฟเวอร์ใหม่ ต้องตั้งค่า Google OAuth, เปิด Before User Created hook และรัน `supabase/sql/02_university_google_auth.sql` ตาม [คู่มือ Google มหาวิทยาลัย](docs/03_design/google-university-login.md) ก่อนใช้งานจริง บัญชีมหาลัยใหม่สร้างผ่าน Google อัตโนมัติด้วย role `user` ไม่มีฟอร์มรหัสผ่านในเว็บ

โค้ดเชื่อมต่ออยู่ใน `src/lib/supabase/client.ts`, `server.ts` และ `src/proxy.ts` ตรวจ claims ที่ผ่านการยืนยันก่อนอ่านบทบาท ไม่ใช้ role จากฟอร์มหรือ user metadata เพื่อให้สิทธิ์ และไม่เก็บรหัสผ่านในแอป ต้องตรวจสิทธิ์ซ้ำใน Server Actions/API ที่เพิ่มภายหลัง ไม่พึ่ง layout เพียงอย่างเดียว ทดสอบกฎ Auth, Dashboard และการส่งเรื่องด้วย `node --test tests/auth.test.mjs tests/dashboard.test.mjs tests/report.test.mjs tests/admin-reports.test.mjs tests/admin-ticket-actions.test.mjs`

### การใช้งานฝั่ง Admin

เมนูหลักมี **ภาพรวม**, **จัดการเรื่องแจ้ง**, **รายงานสรุป** และ **ตั้งค่าระบบ** ใช้ [Branched Menu จาก React Bits](https://reactbits.dev/micro/branched-menu) เป็นเมนูด้านซ้ายในหน้า Admin พร้อมเมนูย่อยทุกสถานะเรื่องแจ้ง หมวดเรื่องแจ้งพับได้ และรายการที่เลือกอ้างอิง URL รวมถึงเมื่อกดย้อนกลับหรือเปลี่ยนตัวกรองสถานะ บนมือถือใช้ปุ่มเปิดเมนูด้านข้าง ปิดได้ด้วยปุ่มปิดหรือ Escape และปิดอัตโนมัติเมื่อเลือกหน้า

โค้ดเมนูปรับเป็น TypeScript ใน `src/components/branched-menu.tsx` และเก็บ CSS ของคอมโพเนนต์ใน `src/components/branched-menu.css` ตามตัวอย่างที่เลือก ใช้ไอคอนจาก `@hugeicons/react` และ `@hugeicons/core-free-icons` พร้อมสีธีมและฟอนต์ของโปรเจกต์ รองรับคีย์บอร์ดและการลดแอนิเมชัน (`prefers-reduced-motion`) ใบอนุญาต React Bits อยู่ที่ `src/components/react-bits-LICENSE.md`

- Dashboard ใช้การ์ดสถิติ 4 ใบ กราฟแท่งรายเดือน วงแหวนสถานะ อันดับอาคาร กิจกรรมล่าสุด และงานที่ต้องติดตาม โดยคำนวณจากข้อมูลเรื่องแจ้งจริงใน Supabase เลือกปีหรือกดเดือนในกราฟเพื่อเปลี่ยนช่วงสรุปได้ กดเดือนเดิมหรือปุ่มทั้งปีเพื่อคืนมุมมองรายปี กราฟแสดงสถานะปัจจุบันของเรื่องที่สร้างในแต่ละเดือนตามเขตเวลาไทย อัตราเสร็จสิ้นเทียบกับเรื่องทั้งหมดรวมยกเลิก กิจกรรมล่าสุดเป็นประวัติของเรื่องในช่วงที่เลือก คิวงานให้เรื่องรอรับอยู่ก่อนแล้วเรียงตามวันที่แจ้งเก่าสุด
- การ์ดสถานะ ลิงก์อาคาร และดูทั้งหมดจาก Dashboard เปิดรายการที่กรองด้วย `year`, `month`, `status` และ `building` ตามช่วงที่เลือก ปุ่มล้างตัวกรองคืนรายการทุกช่วง โค้ดสรุปอยู่ใน `src/lib/dashboard.ts` หน้า UI อยู่ใน `src/components/admin-dashboard.tsx` และกราฟ SVG อยู่ใน `src/components/dashboard-charts.tsx` ใช้ Tailwind และ SVG โดยไม่เพิ่มแพ็กเกจกราฟหรือไฟล์ CSS ใหม่
- บนมือถือแสดงการ์ดสถิติ 2 คอลัมน์ กราฟเลื่อนแนวนอนเพื่อดูครบ 12 เดือนโดยไม่ย่อข้อความ พร้อมช่องเลือกเดือนสำหรับการกดด้วยหน้าจอสัมผัส ตรวจชุดทดสอบการคำนวณ ช่วงเดือน เขตเวลาไทย และลิงก์ตัวกรองด้วย `node --test tests/dashboard.test.mjs`
- จัดการเรื่องแจ้งค้นหาด้วยรหัส หัวข้อ รายละเอียด สถานที่ หรือผู้แจ้ง และกรองตามสถานะ อาคาร และประเภทปัญหา
- หน้ารายละเอียดแสดงข้อมูลผู้แจ้ง รูปแบบ signed URL และประวัติจริง รับเรื่องจาก pending เป็น in_progress ใส่หมายเหตุ ปิดงานเป็น completed พร้อมผลหรือรูป และยกเลิกจาก pending/in_progress พร้อมเหตุผลได้หลังติดตั้ง SQL 04 บันทึกผู้ดำเนินการ/เวลาใน transaction เดียว ป้องกันกดซ้ำและเขียนทับสถานะที่เปลี่ยนไปแล้ว ดู [คู่มือ Admin](docs/03_design/admin-ticket-actions.md)
- การยกเลิกต้องระบุเหตุผล เรื่องที่เสร็จสิ้นหรือยกเลิกแล้วจะไม่สามารถแก้ไขได้
- รูปผลการแก้ไขรองรับ JPG, PNG และ WebP สูงสุด 3 รูป ขนาดรวมไม่เกิน 2 MB บันทึกพร้อมผลการแก้ไขเมื่อยืนยันปิดงาน
- รายงานนับตามเดือนที่แจ้งในเขตเวลาไทย รวมเรื่องยกเลิก และแสดงสถานะปัจจุบันของเรื่อง

ทั้ง User และ Admin อ่านเรื่องจริงจาก Supabase ผ่าน `src/lib/user-reports.ts` ฝั่ง User กรอง reporter_id ของบัญชีที่ล็อกอินเสมอ รวมถึง Admin ที่สลับไปหน้า User ฝั่ง Admin ตรวจ `requireProfile(true)` ก่อนอ่านเรื่องทั้งหมด พร้อมข้อมูลผู้แจ้ง อ่านแบบแบ่งหน้าเพื่อไม่ให้สถิติขาดเมื่อเกินขีดจำกัด API มีปุ่มอัปเดตข้อมูลเมื่อมีเรื่องใหม่ ข้อผิดพลาดไม่ย้อนกลับไปแสดงข้อมูลตัวอย่าง ไม่ต้องเพิ่ม SQL สำหรับการอ่าน Admin เพราะใช้ RLS เดิมจาก SQL 01–03

โครงสร้างข้อมูลอยู่ใน `src/lib/tickets.ts` โค้ด localStorage เดิมใน `src/lib/ticket-store.ts` ไม่ได้ใช้กับหน้ารายการหรือรายละเอียดจริงแล้ว หน้าตั้งค่าระบบและ Bell Toggle ยังเป็น UI ตัวอย่าง การเปลี่ยนสถานะจริงใช้ Server Action และ RPC ที่ตรวจสิทธิ์ Admin ซ้ำ พร้อม ledger คำขอใน schema ส่วนตัวหลังติดตั้ง SQL 04

### การทดลอง Bell Toggle ฝั่ง User

ส่วนหัวทุกหน้า `/user/...` มีปุ่ม Bell Toggle จาก React Bits ขนาดเล็ก กดเพื่อทดลองเปิด–ปิด พร้อมแอนิเมชันกระดิ่งและสีส้มเมื่อเปิด บันทึกสถานะใน `localStorage` คีย์ `fixmfu-demo-notifications-v1` และแสดงตรงกันในแท็บบน origin เดียวกัน ปุ่มรองรับ Enter/Space มี `aria-pressed` และลดแอนิเมชันตาม `prefers-reduced-motion` ส่วนนี้ยังเป็นตัวอย่าง UI ไม่ได้ส่งการแจ้งเตือนจริงหรือขอสิทธิ์แจ้งเตือนของเบราว์เซอร์

โค้ด TypeScript อยู่ใน `src/components/bell-toggle.tsx` และตัวเชื่อมหน้า User อยู่ใน `src/components/user-notification-toggle.tsx` ใช้ CSS จากตัวอย่างใน `src/components/bell-toggle.css` และแพ็กเกจ `motion` ร่วมกับ Hugeicons ใบอนุญาตใช้ไฟล์ `src/components/react-bits-LICENSE.md` ร่วมกับ Branched Menu

หน้าแรก User ใช้แบนเนอร์พื้นเข้ม ข้อความสีขาว/ส้ม และฟอร์มเริ่มแจ้งเรื่องใน `src/components/user-report-start.tsx` เลือกห้องเรียน หอพัก อินเทอร์เน็ต หรือพื้นที่ส่วนกลางแล้วระบุหัวข้อ ปุ่มไปต่อส่งหัวข้อผ่าน URL ไปเติมใน `/user/report` โดยยังต้องเลือกอาคาร ระบุสถานที่/รายละเอียด และส่งยืนยันในฟอร์มเต็ม พื้นที่ที่เลือกปรับตัวอย่างสถานที่ ส่วนอินเทอร์เน็ตเลือกหมวดที่ตรงกันจากรายการที่เปิดใช้งานจริง ไม่เพิ่มหมวดหรือข้อมูลลงฐานข้อมูลโดยอัตโนมัติ

การ์ดสรุป 3 สถานะนับเฉพาะเรื่องจริงของผู้ใช้ที่ล็อกอิน และกดเพื่อกรองรายการได้ มีตัวกรองสถานะ ค้นหาด้วยรหัส/หัวข้อ/อาคาร/สถานที่/ประเภทปัญหา และการ์ดเรื่องแจ้งใน `src/components/user-ticket-card.tsx` พร้อมไอคอนหรือรูปแนบ ข้อมูลสถานที่ อัปเดตล่าสุดจากผู้ดูแล และขั้นตอนรอรับเรื่อง → กำลังดำเนินการ → เสร็จสิ้น เรื่องยกเลิกแสดงแยกจากขั้นตอนนี้และมีตัวกรองเมื่อมีข้อมูล ใช้ Tailwind และ Hugeicons โดยไม่เพิ่มแพ็กเกจหรือไฟล์ CSS ใหม่ ฟอร์มแจ้งปัญหาใหม่ส่งข้อมูลจริงหลังติดตั้ง SQL 03 ส่วนหัวแสดง Bell Toggle แนวเดียวกับปุ่มออกจากระบบโดยไม่มีข้อความตัวอย่างใต้ปุ่ม และมีคำอธิบายเมื่อชี้เมาส์ว่าระบบส่งแจ้งเตือนยังไม่เปิดบริการ

### การทดลอง Glide Select ในฟอร์มแจ้งปัญหา

ช่องเลือกอาคารและหมวดหมู่ใน `/user/report` ใช้ Glide Select จาก React Bits ตามตัวอย่างที่เลือก ปรับเป็น TypeScript ใน `src/components/glide-select.tsx` และเชื่อมค่าที่เลือกผ่าน `src/components/report-building-select.tsx` กับ `src/components/report-category-select.tsx` ข้อมูลตั้งต้นคืออาคาร E4, M-Square และหอพัก F1 พร้อมหมวดแอร์/ประปา ไฟฟ้า และอินเทอร์เน็ต รายการมาจากอาคารและหมวดหมู่ที่เปิดใช้งานใน Supabase ค่าปัจจุบันเป็น UUID ใน input ชื่อ `building` และ `category` ของฟอร์ม แยกค่าที่เลือกของแต่ละช่อง ใช้พื้นขาว ไฮไลต์ส้มอ่อน และเครื่องหมายเลือกสีส้มตามธีมกลาง รองรับการคลิก/แตะ ลากไฮไลต์ ปุ่มลูกศร Home/End Enter/Space Escape/Tab และการลดแอนิเมชัน

เก็บ CSS แอนิเมชันจากตัวอย่างไว้ใน `src/components/glide-select.css` เช่นเดียวกับ Branched Menu และ Bell Toggle โดยใช้ตัวแปรสีจาก Tailwind ส่วนนี้เป็นการใช้ CSS เพิ่มเฉพาะคอมโพเนนต์ React Bits ที่เลือก ไม่ได้เปลี่ยนกติกา Tailwind ของทีม ใช้ Hugeicons และใบอนุญาตเดิม จึงไม่มีแพ็กเกจเพิ่มเติม ฟอร์มส่งเรื่องผ่าน Server Action และ RPC พร้อมตรวจ session และสิทธิ์ซ้ำฝั่งเซิร์ฟเวอร์ ดู [คู่มือส่งเรื่อง](docs/03_design/report-submission.md)

### รูปประกอบในฟอร์มแจ้งปัญหา

หน้า `/user/report` มีช่องแนบรูปแบบไม่บังคับใน `src/components/report-photo-upload.tsx` เพิ่มรูปได้หลายรอบรวมสูงสุด 3 รูป รองรับ JPG, PNG และ WebP ขนาดรวมไม่เกิน 2 MB มีภาพตัวอย่าง ชื่อไฟล์ ขนาดไฟล์ และปุ่มลบแต่ละรูป ลบแล้วเพิ่มใหม่ได้ ป้องกันรูปซ้ำ ตรวจว่าไฟล์เปิดเป็นรูปได้ และคงรูปเดิมไว้เมื่อเลือกไฟล์ไม่ถูกต้อง ค่าของช่องไฟล์ `photos` ตรงกับรายการพรีวิวหลังเพิ่มหรือลบ ใช้ Tailwind โดยไม่เพิ่มแพ็กเกจ
